- 관심 분야: 인프라 및 AI 보안

- 원하는 인상: 진정성 있음 · 차분함 · 지혜로움
- 페이지 목적 초안: 인프라·AI 보안 분야의 채용 담당자와 동료에게 J의 문제 이해 방식과 구현·회고 경험을 보여준다.

## 1. 질문으로 원리를 이해하고 효율을 개선하기

- 강점: 질문을 통해 이해를 다듬고 다양한 상황에 적용할 수 있는 원리 기반 기준을 만드는 태도.
- 상황: AI 음성 키오스크 주문 시스템 해커톤에서 LLM 기반 메뉴 인식 과정의 응답 지연 문제를 확인함.
- 행동: RAG·JSON 캐싱을 활용한 처리 구조 개선을 제안·적용함. TTS 기술 검토와 Figma·Flutter 기반 키오스크 UI 구현에 참여함.
- 확인된 결과 범위: 처리 구조 개선안의 적용 및 UI 구현 참여. 지연 감소 수치나 비교 측정 결과는 제공되지 않음.
- 화면용 요약: 메뉴 인식 과정의 응답 지연을 살펴보고, RAG와 JSON 캐싱을 활용한 처리 구조 개선을 제안·적용했습니다. TTS 검토와 키오스크 UI 구현에도 참여했습니다.
- 근거 자료: 추후 제공. 구조 비교 자료, 공개 가능한 UI 화면 또는 프로젝트 링크 후보.

## 2. 서비스 특성을 이해하고 구체화하기

- 강점: 사용자 경험과 데이터의 제약을 함께 고려해 서비스 방향을 구체화함.
- 상황: 감성 분석 일기 서비스의 기획과 개발 과정에서 감성 분석 파인튜닝에 활용할 데이터의 분류가 한정적이었음.
- 행동: 사용자의 언어 입력에서 분석한 기분을 UI 색으로 표현하는 서비스를 기획하고 UI를 개발·소개함. 전처리를 통한 기존 데이터 활용 효율 개선 방향과 데이터 증강 방안을 소개함.
- 확인된 결과 범위: 서비스 기획 및 UI 개발·소개, 전처리·증강 방향 제시. 모델 파인튜닝 완료나 정확도 개선은 주장하지 않음.
- 화면용 요약: 일기의 감정을 색으로 표현하는 서비스를 기획하고 UI로 구체화했습니다. 데이터 분류의 한계를 살펴 전처리와 데이터 증강을 활용하는 방향도 제시했습니다.
- 근거 자료: 추후 제공. 공개 가능한 UI 화면이나 기획 자료 후보.

## 3. 신중하게 시도하고 회고로 배우기

- 강점: 긍정적이고 신중한 접근으로 다양한 시도를 하고, 그 과정을 돌아보며 성장함.
- 상황: 가이드라인과 바이브코딩을 활용한 앱 보안 프로젝트를 수행함.
- 행동: 바이브코딩 과정을 되짚으며 비밀값·토큰 관련 누락 여부 검증과 규약 적용·확인 등 구체적인 보안 검사 기준을 이해하고 활용함.
- 확인된 결과 범위: 보안 요구사항을 검사 기준으로 이해·활용하는 학습 경험. 검사 대상·실제 발견 항목·수정 결과는 추가 자료 확인 필요.
- 화면용 요약: 앱 보안 프로젝트를 진행한 뒤 AI와 만든 과정을 되짚었습니다. 비밀값과 토큰 점검, 규약 적용과 확인을 구체적인 검사 기준으로 이해하고 활용하며 보안 역량을 다졌습니다.
- 근거 자료: 추후 제공. 민감 정보를 제거한 체크리스트나 회고 자료 후보.

## 표현 및 화면 원칙

- 구현·적용한 일과 검토·제안한 일을 구분한다.
- 지연 감소율, 모델 성능, 취약점 개수, 보안 보장 등 제공되지 않은 결과는 쓰지 않는다.
- 차분한 색과 간결한 문장, 경험 중심 구성을 사용한다. 지혜로움을 자칭하기보다 판단 과정으로 드러낸다.
- 상호작용 후보: 경험별 상황·행동·결과 펼치기. 키보드와 마우스 모두 지원한다.
- 근거를 준비 중인 항목에는 가짜 링크나 임의 이미지를 넣지 않는다.
- C09의 공개 근거 연결은 별도 자료나 확정한 결과 문장으로 충족 여부를 확인하기 전까지 대기 상태를 유지한다.

# 진행 계획

총 4~5시간을 목표로 한 추정입니다. 사용자 답변·외부 계정 연결 대기 시간은 별도입니다.

| 단계 | 예상 | 할 일 | 완료 산출물 |
|---|---|---|---|
| 1. 콘텐츠 결정 | 40분 | 대상·목적·공개 범위·실제 경험 3개 결정 | brief, content-plan, disclosure-policy |
| 2. 화면 설계 | 30분 | 첫 화면에 소개·활동·근거 배치, 경험 관련 상호작용 선택 | decisions 및 화면 초안 |
| 3. 구현 | 80분 | 실제 콘텐츠, 반응형 화면, 키보드 동작 구현 | HTML/CSS/JS |
| 4. 검사·개선 | 60분 | 기준 해상도·링크·명암·키보드·콘솔, 실제 결함 수정 | checklist, defects, 증거 |
| 5. 원격 저장·배포 | 30분 | GitHub 공개 저장소와 Vercel 연결, 익명 접근 검사 | setup, releases |
| 6. 제출 정리 | 20분 | 고정 커밋 URL, 확인법 4줄, 판단 3줄, 결함 전후 | final.md |

## 추적 규칙

요구사항 → Issue → 브랜치·커밋 → PR → 배포 → 검사 증거를 연결합니다.

- 브랜치 예: `feat/introduction`, `fix/keyboard-focus`.
- 커밋 예: `feat: 경험 펼치기 구현 (T01-C19-C21)`.
- 작업마다 worklog에 변경 이유·검증 결과·남은 일을 기록합니다.
- 배포 전에는 관련 기록과 코드를 함께 검토합니다. 기록 전용 후속 커밋은 실제 배포 코드 SHA와 구분합니다.
- 빌드 성공은 브라우저 검사나 과제 통과를 뜻하지 않습니다.

현재: 구조 준비 및 자기소개 초안 정리 완료. 대상 독자와 비공개 범위 확정, 근거 자료 추후 제공 예정. 원격 저장소 생성·배포·과제 제출은 후속 단계입니다.

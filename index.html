01 원인 파악 → 개선 주도

지연의 원인을 찾아 구조를 바꾸다

AI 음성 키오스크 · 해커톤

메뉴 인식의 지연에서 전체 처리 구조로 시야를 넓혔습니다. RAG·JSON 캐싱과 모듈화를 제안하며 개선 방향을 주도했습니다.

상황과 행동 살펴보기 ＋
상황과 발견
단기 해커톤에서 패스트푸드점의 음성 키오스크를 개발했습니다. 사용자의 다양한 메뉴 표현을 인식하려고 매 요청마다 전체 메뉴를 LLM 프롬프트에 넣었고, 실시간 주문에 필요한 응답이 지연됐습니다.
내가 주도한 변화
프롬프트와 전처리의 개별 조정을 넘어, 실시간 주문이라는 목적에 맞춰 전체 처리 구조를 살폈습니다. RAG·JSON 캐싱을 적용하고 처리 단계별로 모듈화하자고 제안했습니다. 더 효율적인 설계 방향을 주도하며 개선 구조를 적용했습니다.
함께 구현한 부분
기성 TTS의 특징을 비교하고 파인튜닝 시도에 참여했습니다. Figma와 Flutter로 키오스크 인터페이스도 구현했습니다.
결과와 한계
본인 회고상 데이터 처리 구조가 개선됐지만, 속도 개선 수치는 측정하지 못했습니다. TTS 자체의 지연도 일부 남았습니다.
다음에 시도할 것
외부 LLM API 의존을 줄이는 방향으로 로컬 모델의 파인튜닝과 처리 구조의 추가 개선을 검토하고 싶습니다. 이는 후속 방향이며 이미 검증한 결과는 아닙니다.
프로젝트 사용 기술
Python · SQL · JSON · TTS · RAG · LLM · Firebase · Figma · Flutter

02 맥락 → 구체화

서비스의 의도를 화면으로

감성 분석 일기 · 기획과 UI 개발

일기의 감정을 색으로 표현하는 UI를 개발·소개하고, 데이터의 제약에 맞는 전처리와 증강 방향을 제시했습니다.

상황과 행동 살펴보기 ＋
상황
감성 분석 일기 서비스를 기획하는 과정에서 파인튜닝에 활용할 데이터의 감정 분류가 한정적이었습니다.
내가 한 일
분석된 기분을 UI 색으로 표현하는 서비스를 기획하고 화면을 개발·소개했습니다. 전처리를 통한 기존 데이터 활용과 데이터 증강 방안도 소개했습니다.
결과와 남은 확인
서비스의 의도를 UI로 구체화하고 데이터 활용 방향을 제안했습니다. 모델 파인튜닝 완료나 정확도 개선을 뜻하지는 않습니다.

03 시도 → 회고

상황과 행동 살펴보기 ＋
상황

결과와 남은 확인
